阅读顺序先讨论 Agent 本身：身份、角色与上下文，以及 Supervisor–Executor 的内部运行分工；再讨论任务、团队工作流、计划和记忆，最后回到开发实践。

七篇均按「一、需求动机 → 二、方案选择 → 三、实现效果 → 四、总结反思」组织。

每篇标题之后先放同一段无标题引文，统一介绍项目和专栏；标准文本保存在 [series-intro.md](series-intro.md)，不再在需求动机里分别改写一段相似介绍。正文从各自有来源的实际案例进入，再解释概念和方案。部署记录、真实执行实验与说明性假设分开标注，不能把示例加工成开发经历。七篇切入案例及来源见[证据索引](evidence.md#开篇案例)。

每篇独立成文，默认读者没有读过本系列、不认识 agent-center，也不熟悉本篇涉及的领域。叙述顺序统一如下：

1. 背景与需求：先说明项目在相关场景里做什么，用具体例子交代困难和约束；必要术语随场景解释，不从内部类名或技术反问起笔。
2. 方案与决策：解释可选方案、选择依据和代价，再说明最终选择及实现机制。历史事实与事后比较明确区分，不编造讨论过程。
3. 实现效果：用代码、页面、数据和案例核对结果，分别说明哪些已经实现、哪些效果得到验证、哪些仍有缺口。
4. 总结反思：基于前面的事实判断做对了什么、做错了什么、哪些边界需要调整，给出明确结论。

行文采用开发手记的口吻：从具体变化和经历逐步引出判断。小标题承接内容，不用“值得反思什么”“我的结论”等提纲式提示语代替叙述；结论仍须明确，并有前文证据支持。避免为了叙事感编造对话、场景或心理活动。四部分结构保留为组织骨架。

术语、缩写、研究编号和跨篇概念在本篇首次出现时提供必要解释；不能用“前文已经介绍”代替铺垫。图表放在读者已经理解其对象的位置，正文说明它支持什么判断。

配图共 31 张：26 张统一材质风格的插画与数据图表，以及保留的 2 张实际页面截图、3 张原论文图。各篇分别为 3、4、6、5、6、4、3 张。内容包括状态同步、执行委派、说明性成本曲线、证据交接、故障过程、身份与材料筛选、计划编辑、记忆传播及开发验收。

写作口径：代码描述以当前仓库为准；历史设计以 ADR、旧版本和论文中的部署材料为准；研究结果使用“在该实验/案例中观察到”的限定语。五篇论文仍是工作稿，尚未独立人工复核；专栏文章不把探索性结果写成普遍规律。文章中的工程主张与实验结论分别陈述，不以样本有限为由回避具体设计取舍。
