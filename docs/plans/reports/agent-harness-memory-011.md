## 1. 研究目的与范围

研究 Agent Center 为什么采用 agent、项目和 team 等记忆作用域，它们在实现中如何存储、写入、同步、检索、注入和更新，以及哪些设计兑现了收益、哪些增加维护成本或妨碍交付。允许得出“效果有限”“依赖人工整理”或“证据不足”，不以创新性或预定负面结论为目标。

核心问题是：**知识怎样从某次执行中的局部经验，变成后续任务可以正确使用、及时更新且有适用边界的共同知识？** 文件存在、Git提交成功、索引列出和模型实际使用分别取证，不能互相替代。

P3研究名字、角色与当次context共享；P5研究跨任务、跨会话的持久知识生命周期。P1的执行体边界、P2的治理流程、P4的版本继承作为关联机制，不重复主张其已有实验证明了记忆收益。特别是P3的短任务context实验不能代替持久记忆实验。

## 2. 先区分四个维度

| 维度 | 研究中的含义 | 必须避免的混淆 |
|---|---|---|
| 存储归属 | 哪个Git仓库/文件维护知识；谁拥有版本历史 | agent私有仓库中的project目录，不自动成为项目共享库 |
| 语义作用域 | 一条知识适用于某agent、任务、项目、team还是跨项目 | 适用于项目，不代表整个项目的所有agent可读 |
| 权限与治理 | 谁可读、提出变更、批准、撤回；谁承担维护责任 | 有角色标签不等于有授权；有审核不等于事实正确 |
| 运行时可见性 | 当次执行收到哪个版本、哪些正文，是否另行读取 | 存储可访问、索引可见、正文已读、决策采用是四件事 |

会话历史、压缩摘要、executor输入、Team规则、项目仓库中的AGENTS.md以及Center业务状态分别登记。它们都可能影响context，但不统一计作“记忆条目”。`global`也须区分agent私有仓库根作用域与Center平台级global仓库。

## 4. 研究问题、竞争解释与反证

| 编号 | 问题/候选机制 | 需要观察的证据 | 反证或竞争解释 |
|---|---|---|---|
| M-RQ1 | project scope寄存于个人记忆是否形成知识孤岛？ | 同项目不同agent在相同有效信息已产生后的可见输入与重复探索 | 知识已通过任务产物/Team规则共享；隔离也可能避免无关信息 |
| M-RQ2 | team共享提高复用，还是把局部经验传播成错误通则？ | 跨任务复用链、适用条件、有效/无效复用及纠正 | 团队共享减少重复；错误也可能来自源事实本身 |
| M-RQ3 | 索引优先能否在节约context的同时保留必要事实？ | 索引、遗漏清单、工具读事件、输入正文、任务结果 | 未读取可能因索引不充分、预算、需求不明确或模型选择；不能一律归因为遗忘 |
| M-RQ4 | 私有笔记何时值得升级为项目/团队共同知识？ | 来源证据、提案、审核、推广后的首次使用及退回理由 | 人工审阅可能阻止错误经验扩散；延迟未必都是无用流程 |
| M-RQ5 | commit冻结与知识更新如何平衡可复现性和时效性？ | 写入/批准/加载/首次采用时间及精确commit | 旧版本可能是有意冻结；不能把所有未即时刷新判作缺陷 |
| M-RQ6 | 谁维护、压缩和废弃记忆，维护成本是否抵消收益？ | 重复/冲突/过期知识、合并删除记录、人工整理时间 | 文本重复可为不同读者降低访问成本；没有计时不能编造人时 |
| M-RQ7 | 学习闭环在哪里中断？ | executor发现→Supervisor接收→记忆写入→后续读入→正确使用 | 原始结果可能无需持久化；有接口不等于生产路径接通 |

为每个机制保留顺利复用、必要隔离、有效审阅和主动废弃等正例。明显系统bug、版本不一致、未接线、读写失败、权限配置错误单独记录并排除出设计效应分析；若不能排除，标为根因不明，不改名为“记忆管理复杂度”。

## 6. 对照实验候选（尚未执行，非预注册）

| 实验 | 保持不变 | 单独改变的因素 | 主要评价 |
|---|---|---|---|
| E1 记忆组织 | 相同事实、权限、任务、模型、总预算 | agent私有project笔记／项目共享库／team共享库／按项目+消费角色选择的共享上下文 | 跨agent必要事实覆盖、独立验收、重复探索、无关事实采用 |
| E2 检索与披露 | 相同库、条目版本、查询权限 | 预算内直接提供必要正文／索引后按需读／元数据匹配筛选；无记忆基线另报 | 正文读取率、必要事实采用率、读工具成本、截断漏失 |
| E3 治理与升级 | 相同候选知识与带真值的审核材料 | 直接写入／明确规则审核／人工或curator批准；人工与模型审核分开报告 | 错误知识进入canonical比例、拒绝正确知识比例、更新时间和审核成本 |
| E4 新鲜度与版本 | 相同任务序列和发生在明确时点的事实更新 | 固定快照／新任务刷新／显式失效通知；不能在一次任务中暗换评价契约 | 过期知识误用、结果可复现性、纠正速度 |
| E5 学习闭环与维护 | 相同历史执行结果、后续任务和信息真值 | 不写回／原文写回／有来源与适用条件的总结／经过审阅的总结 | 后续迁移收益、错误泛化、记忆体积、维护动作与总成本 |

E1两种分析分开：先提供同样正文，仅改变作用域标签以检验语义影响；再通过真实访问路径改变信息可达性，测组织方式的整体效果。后者包含检索机会变化，不能解释成纯标签效应。E2中“直接提供必要正文”是可见性上限对照，不伪装成生产可获得的oracle。

首先用无LLM回放验证每个fixture的权限、版本、检索结果和唯一正确动作，再做完整任务试点。正式实验需冻结任务集、模型精确版本、重复次数、随机顺序、预算、评分规则和停止规则；按同一任务配对，跨模型分报，不把同一事实的多次回答视作独立真实案例。保留格式错误、传输重试与机制错误三个口径。若发现fixture有bug，受影响整个条件剔出主比较，修复后作为新批次保留，不覆盖原结果。

短问答仅检验检索/归属行为；至少另设多步任务及后续任务检验实际交付。没有相应端到端实验时，不宣称某种记忆结构提高自动交付率。

## 7. 指标与证据链

最小分析单位是“知识项版本 × 具备复用机会的后续任务”。每个单位记录来源任务、创建/批准时间、scope、author/curator、repo commit、适用条件、有效期/废弃状态、索引呈现、正文读入、采用行为、交付结果和人工介入。

| 指标 | 分子/分母或统计单位 |
|---|---|
| 必要事实可见率 | 输入或读取结果中出现的必要事实数／该任务已核定必要事实数 |
| 有效复用率 | 正确应用且满足适用条件的知识—任务对／存在有效复用机会且可观察的知识—任务对 |
| 过期知识误用率 | 实际采用已失效知识的对／有更新且读入版本可确认的对 |
| 知识升级延迟 | 来源证据形成→提案→批准→首次可读→首次实际使用，分别报告中位数、分布与删失 |
| 成本与维护 | 每次运行实际token、工具读次数、Git/审批动作和有记录的人时；字节不直接换算token |
| 交付效果 | 独立验收通过、复现失败、人工兜底、放弃、未知分别报；不能以Task终态替代验收 |

后续图表至少包括：①版本化存储与读写结构图；②写入—披露—采用证据漏斗；③scope×失败位置矩阵；④更新时延分布；⑤对照实验配对差异及不确定区间。数据不足则不绘制暗示效果的统计图。
