# P5 记忆研究：有范围的文献比较与操作框架

- 编写/核验：2026-11-03（America/Los_Angeles；UTC 2026-11-04）。
- 对象：P5 工作稿及 memory-011 的记忆机制材料。
- 方法：按与本地问题的关联性选取五项原始研究，核对原论文方法、评价范围及出版信息；这是叙述性比较，不是系统综述，不声称覆盖整个领域。
- 定位：本地证据提供一个部署中的约束适用性失效案例与治理边界分析，不提出新的通用记忆算法，不凭这次检索声称“首次”或“填补空白”。
- AI 单人完成，尚未人工复核。没有运行新模型，也没有增加记忆效果实验。

## 建议替换的研究问题

现有“各层提供什么能力、为什么存储共享不保证复用”包含两个范围不同的问题，应将前者降为系统背景。主问题可收窄为：

> 在 Agent Center 中，已发布并能跨成员读取的完成规则，如何因任务阶段和验收顺序不匹配而阻碍中间交接；现有治理与版本机制能否揭示这种不匹配？

子问题仅保留：①哪些事实证明问题位于适用层，而非未保存或未读取；②条件化规则的可见采用是什么，哪些同步干预使其独立效果仍未识别；③私有作用域、团队发布状态与当次采用为何不能合并评价。

这可由 M02/M03 和全量可得治理/读取记录回答；“哪一层记忆提高多少交付成功率”不能由现有资料回答。

## 可整合正文的主题综述

### 从容量管理到内容更新：已有机制不等于规则适用性保证

长期记忆的保存、选择和更新已有明确方案。Generative Agents 将经历保存为记忆流，结合时近性、重要性与相关性选择记录，并产生反思；MemGPT 通过上下文内外的分层存储及函数调用管理有限上下文；A-Mem 将新经历组织为关联笔记，并允许新内容更新既有记忆的上下文、关键词和标签。这些工作分别处理情境回忆、上下文容量和内容组织，不能概括为“只做存储和检索”。它们所验证的行为可信度、长对话或文档任务，也不能直接换算为软件团队规则的适用性。[1]–[3]

### 从共享经验到权限治理：传播范围与规范效力是不同维度

G-Memory 已将多智能体交互、历史问题与经验组织为层级图，按当前任务和角色筛选经验，并将成功或失败反馈纳入更新。因此，跨成员经验复用和角色相关筛选不是本文的新概念。Agent Center 的局部分析关注另一条边界：一个成员能够访问某项经验，和该经验被授权发布为团队规则，是两种状态；规则正式生效后，仍可能把最终交付约束错误地用于中间候选。这里的“授权不等于正确”是本地治理记录支持的观察，不能据此宣称已有记忆系统普遍忽视权限或规范。[4]

### 从取回文本到任务结果：评价必须与被解释的行为一致

LongMemEval 将索引、检索和阅读分开，并分别评价记忆召回与最终问答，包含知识更新和拒答能力。因此，区分访问与有效使用也不是本文独有的评价思想。本文沿用这一分解原则，将工程规则的评价终点改为具体任务决策：读到了哪个版本、适用于哪个阶段、是否被明确采用、随后发生了什么。读取审计可说明传播通路，无法单独说明规则正确，更无法提供交付收益的因果估计。[5]

### 本研究能补充的内容

五项工作并不提供 Agent Center 中 main 门禁与候选验收顺序的部署证据。本文补充的是这一特定场景的失败解释：知识已能发布和跨成员访问，仍可能因为缺少阶段条件而形成循环约束；条件化规则在后续交接中获得明确采用，但与人工提示、候选证据和图变化共同出现。这个贡献属于可追溯的失效案例和设计边界分析，不能写成对现有算法的优越性证明。

## 建议采用的操作框架

将它称为“本研究的分析框架”，不要称为已被验证的普遍理论。框架不是线性转化漏斗：未发布知识可在同一会话被采用，读取也可能发生在多个上下文。

| 构念 | 定义 | 最小观测判据 | 现有证据 / 不能推出什么 |
|---|---|---|---|
| 保存 | 某个版本的内容存在于相应存储 | 文件或提交可定位到正文 | 可追溯不等于后来被读到 |
| 发布 | 获授权进入特定 Team 的 canonical 状态 | 提案、审核、canonical 正文和 commit 对应 | 授权不等于独立真值核查 |
| 可达 | 指定上下文能经既定接口取得规则 | 正文回执可还原 commit/slug/状态 | 服务端回执不保证完整模型输入 |
| 适用 | 规则对象、阶段、前提与当前合同相容 | 规则条款与合同顺序/权限逐项对照 | 不能只用相似度或更新时间判断 |
| 采用 | 某次决策或动作明确依据规则 | 引用条款、排除理由或状态动作可定位 | 只有相邻时间不满足此判据 |
| 局部效果 | 在固定验收对象上发生可核状态/产物变化 | 节点动作及相应验收证据 | 局部完成不等于 Plan/部署成功；关联不等于净因果效果 |

**区分两种“旧知识”。** 版本陈旧指消费者拿到已被替代的文本；适用性陈旧指文本版本可能最新，但其前提已不适用。230 条回执的版本核对可约束第一种解释，M02 更接近第二种。不要用“没有旧 commit”否定规范过度泛化，也不要把 M02 自动归因于缓存。

**机制链（待外部验证）。** 从最终交付抽取局部经验 → 发布时省略阶段条件 → 消费者将团队通则视为全任务约束 → 与候选先验收后合并的合同相交 → 产生循环等待。必须逐环指出支持来源；其中的心理过程只能作为候选解释，不用模型内在“理解”替代行为证据。

**可证伪的下一步。** 固定候选产物、权限、工具说明、任务合同和验收版本，比较无规则、宽规则、条件化规则、显式替代旧规则四个条件。主指标为正确完成中间交接且保留最终 main 门禁的比例，另计错误放行、阻塞、人工补充与调用成本。相同案例的多次模型运行不是多个独立生产部署；应按任务聚类分析，保留全部条件及失败。若条件化规则只增加放行却破坏最终门禁，就不能判作改进。本轮仅提出设计，未执行。
