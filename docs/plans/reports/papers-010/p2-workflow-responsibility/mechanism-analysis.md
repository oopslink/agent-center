# 三篇论文的机制分层与可识别边界

2026-11-03。主实验运行中建立；尚未读取任务决策内容。实验输入和评分已另行冻结。本文件只组织竞争解释，不预填效果结论。

## 共同问题：表示是否保留了决定下一动作所需的信息

令完整工作状态为s，模型可见视图为φ(s)，正确处置为y(s)。若存在两个合法状态s₁、s₂，使φ(s₁)=φ(s₂)而y(s₁)≠y(s₂)，则任何只依赖φ的确定性决策都无法同时正确。这是直接的函数矛盾，不需要把错误归因于模型能力、训练或人格。它只证明该受限视图不足；不能证明真实部署当时确实只提供了这一视图。

本轮构造12对可核反例，三篇各4对，保存完整状态、共同投影和不同答案。它们是分析性构造，不能计作12个模型失败或12起生产事故。模型实验另外测量事实完整或不完整时的表现，将信息缺失、关系推导、错误选择和持续不推进分别处理。

## P2：责任映射与流程复杂度

1. **关系未绑定。** role说明谁通常做哪类事，当前action还要连接actor、object、scope和authority。W01补的是执行分配的主体，W02补的是分支对象与阶段；同样角色原则允许不同合法实例。bound/distributed在事实相同时测量关系联结负担，不能证明角色少更好。
2. **局部完成替代全局完成。** 某项检查通过或NO-GO报告完成，都是局部目标；若未满足义务没有被交接，就可能出现局部步骤合法、全局目标停留的现象。模型动作检查可发现scope混淆，但一次回答不能建立工作流不活跃。
3. **表示复杂度与实际工作量不同。** expanded只把同一组谓词拆为更多中间gate，不新增测试、等待或参与者。结果只能解释表述深度；真实依赖链延长、通信成本与资源串行化仍需长程任务。
4. **信息边界与授权边界不同。** 不知道负责人需要查询，知道但无权执行需要升级，已经请求外部资源可以等待。把三者都写为blocked会失去恢复条件。模拟器分别保留合理请求/等待与多余escalation，不将谨慎一概当失败。
5. **交接协议是否闭合。** 对非终态且无显式外部等待的工作项，至少需存在一个有授权的下一动作及其责任主体。这是设计检查条件；现有数据没有恢复所有授权和完整轨迹，不能宣称生产闭合性已被证明或否定。
6. **模型层替代解释。** 过长记录可能增加选择负担；一般状态推理、提示敏感和训练模式都可能影响行为。短题差异只能定位行为条件，不是内部注意力、认知过载或“扯皮动机”的证据。

## P3：名字、信息组织与体验

1. **显示字符串不是信息所有权。** 名字可能帮助人类指代对象；知识是否隔离取决于holder/scope/version/permission及实际读取。删去人名不改变这些关系。proper/opaque只改显示标签，稳定ID和权限不变。
2. **个人记忆是持有人索引。** 按holder取上下文可能把跨成员产生的必要事实挡在输入外，这属于选择规则的结果，而不是模型没有读懂名字。缺事实时请求context可正确保护边界，但不能自动交付最终处置。
3. **角色分类不等于决策所需信息集合。** 一个开发者可能需要测试者的失败证据，测试者可能需要发布负责人授权。按producer_role只取同角色事实，会形成与个人隔离不同的缺口。须单列role-only的反例，不能把按角色共享预设为最佳方案。
4. **信息到达与信息使用分开。** all/bounded可能都包含充分证据，前者更多过期或异scope材料；差异须看使用准确性和输入长度。bounded使用完备且正确的元数据，是精确过滤条件，不代表真实语义检索器有同等召回率。
5. **角色不授予权限，版本不只是时间。** 当前有效合同与候选必须和证据相容；旧版PASS与当前FAIL同时可见时，应根据记录范围而非昵称亲近感选择。实验没有向无权者提供私有记录，也不测真实信息泄漏。
6. **情绪价值是另一条结果链。** 开发者已有“团队leader、掌控感、上瘾”的单人回顾自述。可读队友、可见进度和指令得到响应都可能贡献体验；名字的独立作用尚未隔离。LLM匿名对照不能替代开发者交叉使用实验，更不能把该自述诊断为临床成瘾。

## P4：图、产物与验收不是同一状态空间

1. **图变化的直接对象是组织关系。** 任务图G、产物A、合同C、环境E应分别追踪。图节点保留可以维持义务记录，但通过性仍取决于A在C/E下的证据。只观察G会出现同图不同验收的构造反例。
2. **组织继承不推出内容继承。** 父子generation、Git祖先、完整树等价、功能保留分别回答不同问题。后代提交可以删除旧能力；不同SHA也可同树。实验比较是否能恢复候选—树—功能关联，而非把新generation直接当回归原因。
3. **合同变化改变结果归属。** 旧范围撤回、新范围PASS与新需求加入不等于同一任务的重复试验。将scope绑定到验收可减少错误归属；当前实验不比较真正的发布成功率。
4. **累计图与活动图包含不同负担。** 历史节点有审计用途，模型决策时未必需展开。cumulative/active改变18个无活动依赖的已完成节点的可见细节，保留当前义务；它不是静态图/动态图消融，也未测长期记忆丢失。
5. **恢复需要对症。** 代码缺陷、无测试任务、已有证据未挂接、新需求与外部等待分别对应不同处置。改图可能正确承载新检查，也可能无法改变缺少授权的状态。一次选择正确不代表执行或交付完成。
6. **演化收益不能由频次反推。** 代数大、节点增多、后继PASS都受任务难度、追加范围、人工补充与停止规则影响。真正净效果需固定目标/产物/权限，比较可局部续修与必须换代的长期策略，并同时测验收质量和协调代价。
