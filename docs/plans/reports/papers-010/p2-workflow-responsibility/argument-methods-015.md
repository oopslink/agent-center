## 1. 资料发现与观察窗口

全库26,961条消息的词法检索得到429条去重候选；67条原生消息为围绕11个锚点的选定阅读材料，另复读既有分支案例。以上不是故障数或独立任务数。W01、W02的固定区间共28条消息，分别为6条与22条；窗口首尾、发送者纠正、用户消息编码与原始定位见[证据附录](evidence-details.md)。

W01的初始generation为`generation-709baba8`，对应五节点原生快照。首次空assignee及API拒绝仍为PD报告；后续原生快照不能证明更早前态。正文表1和图1保留任务映射，图2区分报告、用户指令、原生快照和系统通知。

## 2. 统计单位与操作定义

用户消息至下一条Agent消息的间隔只表示响应记录间隔；连续用户消息可以共用回复。相邻发送者不同只计一次切换，不推定回复关系或消极动机。人工补充采用互斥主类别，不构成独立双人编码；没有人际一致性系数。

26个非显式夹具Plan共有195个累计generation，根与最后记录配对。seq深度以最长前置路径边数表示，最大拓扑层以相同前置距离的节点数表示；跨assignee边比例只纳入两端负责人已知的边。21个Plan在两端均有可比较边，其余不填0%。累计快照包含完成或废弃节点，不是活动执行集合。公式与底表入口见[原证据附录](evidence-details.md)。

正文中的`〈目标，动作，主体，对象，合同，授权，前提〉`用于组织既有案例解释，不是声称全库完成了这七字段编码。四对受限视图反例为分析构造：相同可见表示对应不同合法处置，仅证明该表示不充分，不能计入生产事故或模型错误。

## 3. 实验实施与效度审计

原实验固定Sonnet 5.5与Haiku 5.5、low effort，经同一CLI运行；每次新隔离进程，无项目记忆、真实工具与会话持久化。8情境×8条件×2顺序版本×2模型共256次。顺序版本调整记录／块顺序，原协议概述中的“标识映射”没有实现；这项偏差保留，不把两个版本当独立随机重复。服务侧不可见输入仍不能完整审计。

原256次响应全部正常返回且模型标识一致。严格评分要求输出格式与四个核心字段同时符合；事后提取唯一内嵌JSON只用于语义诊断，不回写格式失败。W2在要求集成时同时给定`integration_ok=true`，W8未指定回执合同却要求唯一release答案；两题所有条件均排除负面归因，原分数与全部响应继续保留。它们的64次响应中有42次未匹配，不能解释成42次责任错误。

Sonnet的collapsed减expanded原差为4.69个百分点，排除缺陷题后为6.25个百分点，均由输出格式构成；Haiku有效情境各因素差均为0。原联表优势也受缺陷题影响。预定一次字段反馈按固定排序取得24个未匹配输出，恰好全部为Haiku的W2/W8；0/24只表示该反馈未满足原判据，不能估计持续纠错能力。事后修复两题状态／合同后另冻结64次新调用，两模型各32/32，与主分母分开。

全部因素、输入、原始返回、逐字段评分、反例、反馈和修复输入差分见[受控实验附录](controlled-experiments.md)。没有重跑历史生产事故，没有改写原实验数据，没有因本次论证修订产生新的因果证据。
