# 017之后仍需研究的缺口

本轮是对016方案的第一阶段实现，不宣称完成其全部判别研究。

| 问题 | 本轮覆盖 | 仍需什么 |
|---|---|---|
| 短题是否等于执行 | 实际文件、独立worker进程、测试、审查与版本绑定终验 | Agent Center生产版本回放与较长项目任务 |
| 提示是否给出结论 | 只给目标、能力、合同和真实失败；不预设修复责任或下一动作 | 独立人工检查题目与提示，更多措辞集合 |
| 统一身份的作用 | 相同Supervisor/executor结构中的统一／分离身份表述 | 等能力不同拓扑、长上下文、连续失败、主动提醒组 |
| 台账的作用 | 自动提供最新客观工件／worker状态 | 分离信息新鲜度、token成本、显示方式与程序状态维护 |
| 真实交接复杂度 | 相同四工件由两／四worker职责实际交接 | 新任务、并行分支、变化合同、跨项目范围及外部依赖 |
| 行动绑定的作用 | 相同权限／合同／依赖分表或联表 | 缺事实与呈现难度分开；有多个合法对象的复杂关系 |
| 系统bug排除 | H01–H04登记，旧轮全保留并排除；终验副本复放 | 更多并发／评分器测试，不把当前通过称为无bug证明 |
| 修复后独立确认 | 原54条件全组重跑，避免只重跑失败组 | 新未见任务和预定重复；v2仍是看过v1后的探索性复验 |
| 人工兜底与训练来源 | v2内不加人工提醒；商业模型行为可观察 | 提醒干预及同源训练控制；不能从reason文本逆推训练 |

长期故障率、合法升级识别、提醒次数和人工成本尚不能由本轮估计。后续新增任务需先固定合同与独立判定，再收集全部条件和不显著结果；不以追到全对为终点。

新增未闭合案例提出的判别：等任务／角色／预算下，比较只传报告与文件、共享可查回执、明确允许的凭据签发者三项。需保留独立检查和错误凭据反例；未测试的设计建议不算解决方案已验证。审查者承认原件可能存在于别处，不能把其谨慎引用直接编码为全局不存在误判。
