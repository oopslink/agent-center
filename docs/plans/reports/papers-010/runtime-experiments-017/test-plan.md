# 实验harness测试计划

写于模型试点之前；仅实验代码，不涉及产品发布。

| ID | 要检查的实际约束 | 判据 |
|---|---|---|
| T01 | 每个预置应用缺陷失败、参考实现通过 | 全任务向量实跑 |
| T02 | 不同条件的目标与权限事实一致，台账无规范动作 | 自动字段比较与分工审阅 |
| T03 | 工具写入与哈希、只允许角色指定路径 | 原件保留、越界拒绝、不改变候选 |
| T04 | 子进程worker、wait、事件回流与终止 | 无模型脚本worker实跑，不靠假状态 |
| T05 | 最终验收不接受旧候选测试/审查/manifest | 正例过，逐字段失配反例拒绝 |
| T06 | 传输失败/无效JSON/程序错误分别分类 | 可控替代调用，不计成同类错误 |
| T07 | no-active无状态变化与active等待分离 | 不把尚在运行的任务判停摆 |
| T08 | 开发任务端到端模型试点 | 保存全轨迹，主家族不使用 |
| T10 | 元数据兼容且不削弱测试合同 | name/notes通过，缺input、双/无预期、错预期、少于四个不同输入拒绝 |
| T09 | 正式运行冻结、全部结果和模型版本可核 | 输入/代码哈希匹配，缺失不消失 |

这些测试验证实验仪器，不证明被测架构好坏。报告将记录单元/状态检查、真实子进程检查、模型试点与正式实验，分别计数。外部实验仓库没有引入Go goroutine或产品代码修改；不把产品测试覆盖率或部署release声明套用到本次研究。
