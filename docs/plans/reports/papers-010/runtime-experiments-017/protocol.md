# P1/P2真实工件与多轮角色执行实验（003）

状态：事前开发协议；主任务输出前冻结为design-lock.json。日期以America/Los_Angeles 2026-11-04记。不是历史Agent Center二进制的生产重放，也不称所有实证缺口已补齐。

## 问题与操纵

P1：在实际分离的控制者/临时执行者、相同交付合同与权限下，统一逻辑身份与分离协作者表述是否影响失败候选后的自主恢复？持续客观状态台账是否改变多轮行为？身份因素仅改变身份抽象，不改变实际拓扑，因此不作架构净效应或训练来源归因。另设单会话直接编辑参照，显示移除委派的任务可解性，不将其差异归于一个单独机制。

P2：同一组代码、测试、审查与发布工件，由两个合并职责角色或四个分离职责角色完成时，实际交接能否自主闭合？将相同主体/权限/输入输出事实作联结视图，是否影响推进？两/四角色改变真实会话与交接边界，保留相同产物与验收；不声称总通信量、角色提示或上下文分区相同。角色数处理是这种具体组织设计的联合变化。

## 真实执行及共同环境

模型仅通过受控JSON工具协议操作本地隔离文件。每个响应产生的合法工具调用实际执行，工具结果加入该角色的完整会话历史。临时worker在独立操作系统子进程内执行自己的模型调用、写文件和Python检查；控制者与worker的历史隔离，按显式消息和结果传递。控制者可启动worker、读取真实状态、等待完成、请求验收、终止并报告外部需求。一次仅允许一个活动worker，依赖链串行；控制者与活动worker进程可重叠。这里检验串行异步交接，不是并行团队竞态。

CLI safe-mode禁用本地定制、旧记忆、技能、MCP和自动加载；每次调用使用同角色累积历史重建上下文。没有原生聊天session复用或自动压缩。实际模型版本、原始请求/返回、所有尝试、工具结果、文件版本、成本与耗时保存。模型不见研究假说、配对条件、研究汇总评分或oracle代码，但可以看到实际公开检查和发布检查的反馈。系统提示只定义任务目标、工具能力、权限和返回语法，不含“失败必须恢复”“名字不会改变行为”“复杂流程有害”等答案原则。

每个主任务的前三个向量是运行期间可见的公开检查；其余至少五个只在episode结束后，对终止时保存的工件副本执行。独立终验分别报告全向量及额外隐藏向量；公开检查通过不等于独立终验通过。模型自己写的测试也与文字合同核对，但不会收到参考实现。真实测试回执必须早于对应版本的pass审查，不能由终验补出回执倒推审查已经有效。

P1每个试验从同一脚本化executor-00产生的错误实现和失败交接开始：独立进程写入预置实现并实际运行Python检查，记录failed结果后退出；controller面对同一可修复的失败worker结果。该候选是研究者预置的恢复机会，不伪装成自然模型错误或LLM生成的初次失败。后续代码由真实worker模型产生、检查和修改。失败机会全条件固定，避免只选择自然出错的运行。台账只呈现事实、工件版本和最后检查状态，不生成下一动作、应由谁承担或修复建议。两组都保留全部工具历史；台账还主动读取当前工件与worker状态，因此是持续可观测性供给，包含新鲜度和免inspect回合的作用，不称纯排版因素。token与动作代价照实报告。统一/分离组保持Supervisor和executor词汇相同，只改变归属关系；身份表述同时作用于控制者和新worker。

P2要求module.py、test_cases.json、review.json和manifest.json四类工件。短链为builder（实现/测试）与verifier（审查/发布）；长链为implementer、tester、reviewer、integrator。两种行动视图拥有同样的主体能力、工件要求与依赖，差别为分表或联结显示。视图不给出推荐下一动作或替模型发起交接。

## 任务与样本

开发任务独立于主任务，用于接口和状态检查；不计入主样本。主任务P1/P2各三个不同函数家族，均有正常、边界、错误输入等公开文字合同及私有验收向量。每家族在两个固定模型claude-sonnet-5-5、claude-haiku-5-5上运行所有条件，每条件一次。P1为2身份×2台账×3任务×2模型=24，加每任务/模型一个单体参照=6；P2为2组织×2视图×3任务×2模型=24；总54个主episode。顺序用固定seed 20261104打乱，任务与模型内配对。没有随机重复，不能估计稳定发生率或给出总体显著性；三个任务族也不是三个生产部署。

任务实现、实际测试向量和评分器均在主输出前固定。开发与主任务族分离，但主任务仍由本研究AI构造，分工AI审阅不等同独立人工内容效度验证。研究者不根据主结果增加难度、删除通过任务或只重复失败任务。

## 操作预算、结果与停止

P1控制者最多12个决策回合、最多3次worker启动；单体参照同为12回合。P2最多18个控制者回合、最多6次worker启动。每个worker最多6次决策。所有角色可以提前结束。工具wait等待已有worker的真实结果；wait且无活动worker只返回事实，不推荐下一步。回合预算只计模型决策，不把工具耗时当决策。

主要终点为预算内控制者声明完成且独立验收通过。另报初始固定恢复预算、首次controller检查失败时的剩余预算、从完整事件派生的worker检查失败、最终工件实际通过、错误完成宣告、请求外部输入、无活动worker且未改文件的动作总数（含有用检查/读取，不能作为停摆数）、格式/权限错误、启动/交接数、自然候选失败与恢复、调用量和成本。P2还检查测试确实针对当前候选运行，审查/发布引用的文件哈希匹配。验收失败不结束episode，返回实际失败项，仍允许合法动作。预算耗尽、提前放弃、合法等待、运行故障分别报告。工具仍运行时不判停摆；结束时先poll区分仍运行与已完成未收取，使用跨进程文件锁冻结一致工件版本后验收。若已冻结产物合格，不仅因子进程尚未退出而判失败；最终等待退出并单列晚到产物，不回填终止快照。原子写入、全部检查、回执与终止快照共享同一跨进程锁，避免混合版本制造假通过。

主要结果不用LLM解释评分。责任外置仅作为带原文的探索性行为编码，不能从失败状态推断confusion。引用正例/反例使用全表，并按任务/条件顺序选择定位，不只挑最符合假说者。当前任务均不要求外部权限；request_external只按实际行为单列，没有用真实外部权限缺失的对照估计合法升级识别能力。不能把本组任务中少请求人工解释为一般场景下总应继续执行。

## 故障排除与修复规则

预置应用代码缺陷是待修工作，计入任务；模型新写的语法错误、错结果、死循环或不合权限调用属于模型/任务结果，不归为系统bug。CLI传输异常允许一次相同请求重试，两次原件均保留；仍失败则episode标记transport_invalid，不记行为错误。运行harness的权限检查、版本写入、事件丢失或评分器错误是系统缺陷：保留原episode，排除整个相应任务×模型匹配块的因果比较。修复版本必须另留差分、锁和新运行ID，不能覆盖旧结果或只重跑失败条件。实际发现会逐项记录，不能先称全部无bug。

## 过程与预算

先执行无模型状态/工具/评分契约测试及开发任务试点，再冻结主设计。每次CLI报告预算上限0.35美元、传输90秒；主批报告价达到40美元后停止派发新episode，已在运行的episode继续完成，因此这是派发阈值而非严格总额上限；四episode并行。报告价不是实际订阅扣费。若触及预算/服务中断，按缺失单列，不补造结果。完整原始档案留本地；仓库保存协议、脚本、派生数据、图表和复现入口，不写入凭据。

## v2修订：H04仪器修复后的整轮复验

v1在34个episode完成后停止；20个未启动。旧轮全部退出后才修改活动runtime，原始请求、输出、工件和冻结源码保存于episodes-v1、setup/main-frozen-source及design-lock-v1.json。H04：合同没有禁止测试用例带name，但评分器要求键集合恰好等于input/output或input/error，导致正确测试被误拒绝。v2接受描述性附加字段，仅核对input与唯一output/error；补充具体错误位置，全部条件使用同一工具说明。缺少字段、矛盾预期和不足四个不同输入仍拒绝。

v1全部退出主要比较，不仅删除失败样本；54个原计划条件全部使用v2新ID重跑。任务、模型、顺序、因素、预算和主要分析代码不变。因研究者已见到v1结果，这轮属于观察旧结果后修复仪器的探索性复验，不能称未见主任务的独立确认。主分母仅计v2，不与v1累加；v1正反结果全部公开列账。主结果仍可能出现新仪器缺陷，按既定排除规则处理。Python相等比较的数值类型歧义额外作原始终验检查，不以检查通过宣称穷尽评分器正确性。
