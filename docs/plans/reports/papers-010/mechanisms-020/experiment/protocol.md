# 020：两个不同的受控处置问题

冻结协议早于任何本批模型调用。独立 CLI 会话，两款模型、两个固定任务变体，每格两次（工单标记亦变）；固定调度种子不是模型随机种子。一次处置最多三轮；inspect 或格式失败消耗一轮，保留全部响应与终止状态。只用模拟工作台及新构造的无标识材料，不调用生产服务。本轮不是软件开发、生产上线、跨会话长期记忆的实测。

P3：围绕角色上下文研究中跨角色检查、旧候选两类缺口，同一模型、输入事实、稳定机器 ID、角色、权限不变，仅删除 display_name 字段、赋予个人名或赋予重复角色标签。另一因素替换可见凭据：按生产者角色只给本人的旧候选回执；按当前任务给经授权的跨角色测试回执。两视图各一条，后者与当前候选匹配，分别为 pass/fail。任务范围和检查结果同时改变的是信息供给，不是现实检索算法或权限等级；在旧凭据条件下两个潜在真值均不可区分，不算两种独立的可见情境。按记录所允许的合适操作分别为（有证据）accept/reject、（无证据）request。另记实际解决当前候选（缺据请求不是已解决）、错误接受和首次动作。48 个固定单元，24 个不同条件组合，不以模型响应证明人类体验或长期交付率。

P5：据 M02、M03 重建远端不可变候选未入 main 时的两个阶段。两种合同分别要求提交候选供下游独立验收、最终已合入 main 才能关单。独立验收状态随阶段设置；在每个阶段固定全部事实，仅替换随输入披露的 Team 记忆版本：无、无条件通则、带阶段条件、旧新同列并标明替代。不是重演原始对话。32 个单元。以工单合同为独立评分基准：中间节点 close，最终阶段 hold。宽规则与中间任务确有规范冲突，hold 记作“未实现合同交接”，不指控模型认知错误；另外保留是否解释冲突、是否错误关闭最终门禁。注入已到达的记忆不测保存／检索成功，带替代关系条件不等于未标替代的简单并存条件。一次模型响应不足以证明记忆是历史行为的唯一原因。两篇不共用一个评分分母。

程序检查每个命名组除显示字段外完全一致、每个规则组除记忆外完全一致、操作和评分映射、无答案键进入模型输入。请求仅给合同和候选动作，不告知研究目的、评分映射、预期效果或优胜条件。没有根据模型输出来回改题或追加试验。记录 CLI 传输异常、格式异常、超过上限和所有正反方向；不把这些当作系统设计失败。作为探索性同材料描述，不进行独立样本显著性检验。AI 研究，未经人工复核。
