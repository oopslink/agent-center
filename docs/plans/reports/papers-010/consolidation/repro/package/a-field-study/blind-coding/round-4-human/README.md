# 请你帮一个忙：给 15 条记录分类

大概 40 分钟。不需要你了解这个系统，也不需要你懂学术规范。

## 最要紧的一条：请你自己判，不要让 AI 代判

这一轮的全部意义就在于**有一个人照着判据判一遍**。我们已经有两份由模型做的编码，
它们之间高度一致，但那恰恰说明不了判据对人是否清楚——所以如果这一份也由模型做，
这一轮就白做了。

查资料、问同事都没问题；把记录贴给 ChatGPT／Claude／Copilot 让它给判定，不行。
如果某条你确实判不下来，正确做法是填 `D` 并在备注里写缺什么信息（见下）。

## 背景（只需要知道这么多）

这是一个多 AI Agent 协作开发软件的系统：若干个 Agent 分别扮演产品、开发、测试、
集成等角色，互相派活、交接、验收。下面 15 条记录都是某个 Agent 在协作过程中说的话。

有一篇论文要把这类记录分成几类。分类是人判断出来的，所以需要**不止一个人**独立判一遍，
看不同的人会不会落到同一类上。你就是那个人。

## 你要做什么

1. 读 [codebook.md](codebook.md)（判据定义，约 10 分钟）。五类：
   **A 责任外置 / B 合法升级或等待 / C 技术故障 / E 自行承接 / D 无法判定**。
2. 打开 [sheet.md](sheet.md)，先把开头那三行基本信息填上（见表内说明）。
3. 逐行点开 `records/NN.txt` 读那条记录，在「判定」列填一个字母，
   「备注」列写一句你为什么这么判。
4. 填完把 `sheet.md` 发回来就行。

## 四条要紧的提醒

- **「D 无法判定」不是弃权，是一个正当答案。** 记录太短、看不出当时有没有权限、
  或者两类都讲得通——都填 D，在备注里说缺什么信息。把不确定的硬塞进某一类，
  会让论文的结论被夸大。我们宁可看到一堆 D。
- **只看记录里写了什么，不要推测后来发生了什么。** 判据第 §1 节专门讲这一条，
  请先看完它。
- **备注每条都要写**，一句话就够。分歧是有用的结果，所以你为什么这么判，
  比你判成哪一类更重要。
- **不要去猜别人会怎么判，也不用和谁凑一致。** 你的编码会和另外三份独立比对，
  不一致本身就是我们要报告的东西。

## 你不会看到什么，为什么

你拿到的只有判据和 15 条记录。论文正文、另外三份编码、以及这些记录在论文里被归成了
哪一类，都不会给你——给了就不是独立编码了。

## 署名与用途

你的编码结果会进入一篇公开论文：一致率、以及**逐条分歧（含你写的备注）**都会列出来。
不署作者，但会在致谢里写明你做了这一轮独立编码（你不愿意具名的话写"一位外部编码者"）。
如果你不希望自己的备注原文公开，填完说一声，我只用分类不用备注。

记录内容是软件开发协作记录，已去掉本机路径、用户名与主机名。里面的仓库名、分支名、
提交哈希是真实的工程内容，不涉及个人隐私数据。
