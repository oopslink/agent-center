# papers-010 合稿设计：从五篇初稿到两篇可发布论文

**状态：** 设计稿，待批准后进入实施计划
**日期：** 2026-11-04
**对象：** `docs/plans/reports/papers-010/` 下的 P1–P5 五篇初稿

---

## 1 意图与起因

`papers-010` 现有五篇中文初稿（P1 身份与责任连续性、P2 工作流复杂度、P3 命名与上下文、P4 DAG 演化、P5 团队记忆），目标是投 arXiv。对五篇正文与底层数据（`mechanisms-020/`、`runtime-experiments-017/`、`research-validity-016/`）的核查发现四类问题，都不是润色能解决的：

1. **主张强度超出证据等级。** 标题、摘要和结论写成了效应比较（"costs and quality benefits"、"系统交回未显示优于一次提醒"、"不应有个人名字"），而每篇的"证据边界"一节又逐条撤回这些比较的成立条件。读者看到的是自相矛盾的文本。
2. **五篇共用同一口井。** 230 条读取回执同时支撑 P3 与 P5；I05 案例同时进 P1 与 P2；26 个 Plan 的结构统计（节点中位数 8→17.5）在 P2 §4.6 与 P4 §4.5 作为两个独立发现出现；P1 §4.8 与 P2 §4.8 共用同一个运行器、同三个任务家族、同一批 54 个条件，两篇的方法段落有整段逐字重复。每篇末尾的"跨篇引用不构成独立重复验证"声明在单篇阅读时不可见。这构成 salami slicing。
3. **受控实验普遍撞天花板。** 六组实验近 1200 次调用几乎只产出零差异（P1 64/64、P2 96/96、P3 全 8/8、P4 96/96、P5 4/4）。原因在设计里写明了：P1 §3.5 承认 512/512 个输入已声明 controller 负责修复，P2 §3.5 承认全部输入已要求不得把已授权准备工作交给人，P4 §3.5 承认输入已规定成果丢失时恢复基线——答案写在题面里。叠加任务过易（24 次函数任务全过）与每格 n=1，这些零结果不支持任何结论，而 P3 §6.2 自认"没有进行等效性检验"。
4. **规范项不合格。** 五篇将 "OpenAI Codex" 署为共同作者，与 arXiv 2023-01-31 政策直接冲突（生成式 AI 不得列为作者，只能披露使用）。伦理声明为"状态尚未由作者声明"，数据可用性为"保存在授权本地档案；开放许可和脱敏范围尚未确定"。

**本设计的意图：** 把五篇合并为两篇按证据类型切分的中文论文，使每篇的主张强度与其证据等级一致，并满足 arXiv 的发布规范。不追加新的科学主张。

## 2 目标

1. **两篇，按证据类型切分**，不按主题切分：
   - **A 篇｜现场研究。** 用一个冻结时间窗内的部署记录（消息、任务动作日志、generation 快照、Git 对象、规则读取回执、治理事件）解剖多智能体交付中的绑定断裂。结论停在描述与机制层。
   - **B 篇｜受控实验。** 重建运行器实验，集中测量能做出效应的两个点：协调成本与跨会话凭据认可。
2. **两篇证据不重叠。** A 篇只用历史部署记录，B 篇只用新实验数据。旧的短题实验与旧运行器批次进 B 篇附录，作为仪器校准与天花板诊断，不作为结果。
3. **主张强度与证据等级逐句对齐。** A 篇正文、摘要、标题不出现效应比较措辞；B 篇的主张限于实际操纵过的因子。
4. **B 篇的实验有可测效应。** 通过率既不在天花板也不在地板；提示中不预告处置原则；设计在跑正式批次前冻结；任务家族划分开发集与留出集。
5. **规范上无已知阻塞项。** 作者署名、AI 使用披露、伦理与数据可用性声明可落地。注意这不等于"投稿就绪"：英文版与 arXiv 投稿资格均不在本阶段范围内（§3），本阶段的终点是中文定稿。

## 3 非目标

- 不追求因果识别或架构净效应估计。单部署、回顾性、目的性选例不可改变，A 篇必须接受这一定位。
- 不做人类被试研究。P3 §4.6 的单人体验自述不升级为结论。
- 不对生产部署做任何干预。
- 不做系统性文献综述。
- 本阶段不产出英文版。arXiv 自 2026-02-11 起要求非英语投稿附完整英文版（英文在前，允许机器翻译），因此翻译是后续独立阶段的必需项，不是可选项。
- 本阶段不处理投稿事务。arXiv 自 2026-01-21 起对所有分区收紧 endorsement，单一无隶属作者需要 endorser；这是数周量级的前置项，但按负责人决定推迟，不在本阶段规划。
- 本阶段结束时不投稿，也不声称"可投稿"。

## 4 反目标（即使"做完了"也算失败）

- 任何一篇出现"X 优于 Y"而支撑只有 n=1 或一个无功效的零结果。
- 两篇把同一条原始记录各自当作独立证据。
- 为凑结论在出错题上反复修题直到全对，而不在新留出情境上检验。
- 继续用堆砌限制条款的方式替代主张降格——正文照旧说大话，末尾一段免责。
- 合并后出现第三篇、第四篇"衍生稿"。

## 5 约束

| 约束 | 后果 |
|---|---|
| 单部署、回顾性、目的性选例 | A 篇只能做描述与机制，不能给发生率 |
| 历史部署版本、完整模型输入、原模型不可恢复 | 部分案例永久停在"参与者报告"证据级 |
| 无独立人工编码者 | 现有全部分析均未人工复核，须在两篇中明示 |
| arXiv 自 2026-02-11 | 非英语投稿必须附完整英文版（英文在前），机器翻译允许 |
| arXiv AI 政策 | AI 不得署名，须披露使用 |
| 实验投入需控制 | 低档模型、先试跑、总调用设上限 |

## 6 已经定下的决定

### 6.1 由项目负责人决定

- 目标平台为 arXiv，定位是"符合规范、逻辑自洽的正常学术论文"，而非追加新发现。
- 可以合并，不保"五篇"形态。
- 接受按证据类型切成 A/B 两篇。
- 正文先写中文，本阶段不要英文摘要；后续再整体翻译。
- 允许继续跑模型调用、补受控实验，但要控制投入。
- **实验预算硬上限 200 美元（按报告价计），按设计跑满**：两模型保持交叉，开发集与留出集齐备，每格 n≥4。超限停下报告，不自行扩量。
- **先不处理投稿**，先把论文写出来。投稿资格与英文版推迟。
- 三项规范处置按设计者推荐执行：人工复核做限定范围的子集判定；数据可用性出只含派生物的脱敏复现包；伦理采用自我声明、不声称获批或豁免。

### 6.2 由设计者决定（我的判断，非负责人拍板）

- **统一框架用绑定六元组。** 沿用 P2 §3.1 已有的 `〈目标，动作，主体，对象，合同，授权，前提〉`，把五篇的主题重述为同一结构在不同边界处的断裂：责任（P1）、凭据（P2）、信息（P3）、成果与合同（P4）、适用范围（P5）。A 篇按这六类断裂组织章节，不按原五篇主题组织。
- **署名改为 oopslink 单一作者**，AI 参与写入"AI 使用声明"。依据 arXiv 政策。
- **仪器沿用 `runtime-experiments-017` 的运行器**（真实写文件、真跑 Python、真起 worker 子进程、产物版本绑定终验），只更换任务与条件。
- **旧零结果不删除**，进 B 篇附录作为仪器校准与天花板诊断，并说明为何重做。
- **P3 的角色读取重合度分析（§4.5、§4.7）删除。** 表 4 的四种口径给出 0.074／0.063／0.142／0.033，表 6 删层后范围跨过 0（−0.0443 至 0.0798），即结果完全由汇总口径决定。保留它等于保留一个自我抵消的分析。
- **P3 的命名实验（§4.9，48 次全 8/8）降为 B 篇附录的零结果记录**，不作为任何论文的结论来源，除非在 B 篇中补做等效性检验设计。
- **结构统计大幅压缩。** P2 §4.6 与 P4 §4.5 的重复部分合为 A 篇一节；边 Jaccard、父节点保留率等不支撑论点的描述量移入附录。

以下为评审检查后补充的决定：

- **A 篇用既有冻结快照，不重新抽取到新截止点。** 现有普查数字（2,221 个 Task、1,238 个带动作日志、2,527 条动作、230 条回执、26 个 Plan）全部来自那次抽取。部署至今仍在运行，重抽意味着重算五篇份量的全部表与图，并重开案例纳排（又与 §11.1 的人工编码互相缠绕）。因此 A 篇的范围句写"一个时间窗"，不写"整个部署"。
- **"禁用发生率"的准确含义**：禁止的是外推性的发生率与比率，不禁止在完整记录集上报计数。否则 P1／P4／P5 的定量内容会整段离开正文，这不是本设计的意图。
- **实验二需要改仪器，不只是换条件。** `runtime-experiments-017` 的传输层本就"不共享完整工具历史、合同也不限定签发者"，所以"共享可查询回执对象"与"明确规定签发者"是新传输与新合同代码。按独立工程阶段规划，配自身测试套件与新的 design-lock，并先用一个 rt017 旧条件做桥接重跑。连带后果：旧批次不再是"同一仪器的校准"，B 篇附录的定位改写为"前批次及其天花板诊断"。rt017 的 H04 缺陷曾在批次中途暴露、迫使 54 格全部重跑，这一风险按真实概率计入排期。
- **实验二的终点重新定义。** 那次凭据不认可在 54 个 episode 中只出现 1 次（约 2% 基率），任何样本量都无法把"是否发生"当终点。改为由构造诱发：让控制者持有在自身工具历史中可证明看不到的跨会话产物。主终点取"重复索证轮数"与"预算内闭合"；worker 启动预算放宽到不构成约束，不作为交叉因子；掺入的无效回执反例单独计分，不并入主终点。
- **零结果的停止规则。** A 篇是保底交付物，B 篇在试跑后设 kill point：若 30 次以内的试跑无法把通过率调离天花板与地板，B 篇降级为方法与仪器报告，不强行产出效应主张。主终点取连续量（决策数、索证轮数——rt017 中唯一出现过方差的维度），因此质量终点上的零结果可以作为有界零结果报告并给描述性区间，但不做等效性声明，除非预算容许按功效计算放大 n。禁止"迭代到出现效应"。
- **B 篇的每个终点必须脚本可核验**，不得因评分引入新的"未经人工复核"限制。

## 7 两篇的内容归属

### A 篇｜现场研究（描述 + 机制）

| 来源 | 并入内容 | 对应的绑定断裂 |
|---|---|---|
| P1 §4.1–4.5 | dev2／integration-dev／tester3／dev3 案例；2,527 条动作的归属审计；I04 启动责任时序 | 责任 |
| P2 §4.1–4.6 | W01 分配、W02 分支交接、Graph／Spark 独立验收、NO-GO 报告 | 凭据、剩余义务 |
| P3 §4.1–4.4 | 身份配置与显示名分离、治理授权拒绝、命名成员间的事实传播、230 条读取回执 | 信息 |
| P4 §4.1–4.6 | Mermaid／Access／Insight／Spark Host 六案例；169 次父子转移；十项 Git 核验 | 成果与合同 |
| P5 §4.1–4.5 | 治理统计、读取覆盖、宽 main 规则与中间节点的循环、条件化规则正例 | 适用范围 |

A 篇的贡献陈述：**一个运行数月的真实多智能体开发部署的失效解剖，带产物级（Git 对象、回执、动作日志）核验。** 这类材料公开记录极少，描述性定位本身就是贡献。禁止出现的措辞：净效应、优于、收益、发生率、学习曲线。

### B 篇｜受控实验（效应）

**实验一｜协调成本。** 因子：角色数／交接数 × 凭据可达性。主终点：独立验收通过率、控制端与工作端决策数。每格重复次数由试跑通过率决定，下限 4。

**实验二｜凭据认可。** 把 `runtime-experiments-017` 中那次停摆的机制单独立为因子：只传报告与文件 ／ 共享可查询回执对象 ／ 明确规定签发者。掺入一张无效回执作反例，确认改进不是让模型变轻信。

**设计纪律：**
- 提示只给目标、合同、权限、工具语义，不预告"失败由你修复"一类待验证原则。
- 任务须有真实失败空间：规格内含可发现的歧义、多文件、或审查者必须抓到一个真 bug 才能通过。
- 先做一次小规模试跑（一次性、不进结果），确认通过率不在天花板也不在地板，再冻结设计。
- 任务家族划分开发集与留出集；主结果与排除规则在看留出集输出前固定。
- 材料修复必须在新留出情境上检验，不得只在出错题上追到全对。
- 记录并公开全部条件，包括不显著结果。

## 9 投入控制

- 模型固定低档档位（Sonnet 5.5 / Haiku 5.5，low effort），两者保持交叉，沿用既有 CLI 调用方式。
- 试跑阶段上限 30 次调用，用于定任务难度，不进结果。
- **正式批次报告价硬上限 200 美元**，超限停下报告，不自行扩量。
- 成本锚以 `runtime-experiments-017` 的真实数字为准：主批 54 个 episode 报告价 6.31 美元（003 全批 9.77 美元、694 次模型尝试），Sonnet 四角色单格约 0.5 美元。两个析因实验按 n≥4、含开发集与留出集、两模型交叉估算约 150–400 个 episode，即 50–200 美元量级。设计文档早期引用的"0.21 美元"来自 `mechanisms-020` 的 80 次单轮处置，不适用于多轮运行器批次，已更正。
- 墙钟同样是约束：rt017 规模的批次需数小时，排期按此计。
- 裁剪优先级（仅在逼近上限时启用）：先减留出集的任务家族数 → 再减每格重复到 4 → 再收缩到单模型（保留 Haiku，它是唯一出现过方差的一臂）。不以删除因子水平的方式省钱，因为那会改变主张。
- 不做后验重试、不做"追到全对"的追加批次。

## 10 留给执行者的

- 具体任务家族的选择与难度调校（须由试跑结果决定，不预先写死）。
- A 篇的章节编排与篇幅分配（六类断裂的详略取舍）。
- B 篇每格重复次数（由试跑通过率与功效粗算决定，下限 4）。
- 两篇的目标 arXiv 主类（cs.SE 或 cs.MA）与参考文献的补充范围。

## 11 规范三项的处置（已定）

1. **人工复核——限定范围的子集判定。** 不追求正式的双编码者一致性：负责人是系统所有者，不构成独立编码者，宣称"独立"是另一个规范问题。做法是从 A 篇的案例片段中随机抽 20–30 个，由设计者出一份不含结论的盲编码表（只给原始消息／动作记录与判据定义），负责人逐条判定"责任外置／合法升级／技术故障／无法判定"，然后报告人工判定与 AI 编码的一致率及分歧条目。论文表述为"作者对子集作了人工判定，一致率 X%"，不写"独立复核"。
2. **数据可用性——出只含派生物的脱敏复现包。** 原始协作对话不公开。公开动作日志派生表、读取回执审计的脱敏版、169 次父子转移表、Git 对象哈希与核验脚本，以及 B 篇实验的全部输入、原始响应与评分脚本（实验数据无隐私问题，可完全公开）。效果：B 篇完全可复现，A 篇统计可复算，案例可追溯但不可还原到个人。
3. **伦理——自我声明，不声称获批。** 表述为：本研究使用作者自有系统的既有工程协作记录，非人类被试研究，未新增用户实验，未采集第三方个人数据；发表前对可识别信息与内部路径作脱敏。不写"已获批准"，也不写"经判定豁免"——无依据不可写。
